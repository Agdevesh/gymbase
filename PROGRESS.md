## Decisions

- Single `User` table per gym with a `Role`; a member who logs in gets a `User` with role MEMBER linked via `Member.userId`.
- Money is integer paise. GST stored per invoice (`gstPercent`, `gstPaise`).
- Each gym is identified at login by its `slug` (no subdomains yet).
- Prisma 6 chosen over 8 (rc) for stability. shadcn/ui deferred until a module needs real components; plain Tailwind so far.
- Files in Postgres rather than S3/Blob to keep the stack to Vercel + Neon; swap `storeFile` in `src/server/members.ts` for object storage if the DB grows.
- Phones stored as E.164; `normalizePhone` assumes +91 for bare 10-digit numbers.
- `Membership.renewedFromId` chains renewals and upgrades; freeze extends `endDate` by `frozenDays`.
- Editing a plan never changes existing memberships (they keep their own `pricePaise`); retire a plan instead of deleting it.
- QR payload is `GB:<32-hex qrToken>`; `tokenFromScan` also accepts bare tokens and `/checkin/scan/<token>` URLs. Duplicate check-ins within the 4 h window are ignored (reported as "already in").
- Payments never carry credit: an amount above the outstanding total is rejected. Refunds are separate `Payment` rows (`kind` REFUND) that decrement `Invoice.paidPaise`. Cash closing only stamps CASH payments; UPI/card reconcile with the bank.
- Razorpay plan ids map to GYMBASE plan codes through env (`RAZORPAY_PLAN_STARTER` etc.); the gymId and planCode travel in subscription `notes` so the webhook needs no lookup table.
- Any FK to `User` that is reachable from `Gym` must cascade (seed deletes the demo gym); RESTRICT there breaks teardown.
- Reminders without an API provider are a to-do list for reception (wa.me / sms: / mailto: links + "Mark sent"), never silently faked. Cron runs at 04:30 UTC = 10:00 IST, matching `sendTimeFor`.
- pdfkit's built-in Helvetica has no ₹ glyph, so PDFs print "Rs.".
- YouPI-PG (linked by the owner) has no LICENSE file and `"license": "Commercial"`, so none of its code was used; the fixed-amount QR + bank-alert verification is GYMBASE's own implementation of the same idea. UPI auto-verification matches on exact amount only; equal-amount collisions are resolved by the code in the SMS or by hand, never guessed.
- Form checkboxes use a hidden `off` input before the checkbox; server actions read `formData.getAll(name).includes("on")`.

## Android app: build, sign, Play Store

- Local build: `cd android-app && npm ci && GYMBASE_URL=https://<your-domain> npx cap sync android && cd android && ./gradlew assembleDebug` (needs Android SDK + Java 21). Debug APK lands in `android/app/build/outputs/apk/debug/`.
- Release via CI: every push to `main` that touches `android-app/` (or a manual run of the "Android APK" workflow on main) publishes a GitHub release `android-v0.1.<run>` with `gymbase.apk`; a tag `v1.2.3` publishes under that tag. Set repo variable `GYMBASE_URL` to the production domain once it exists.
- Signing: generate a key once, `keytool -genkeypair -keystore gymbase.jks -alias gymbase -keyalg RSA -keysize 2048 -validity 10000`, then add repo secrets `ANDROID_KEYSTORE_BASE64` (`base64 -w0 gymbase.jks`), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Until those exist CI signs with a throwaway key, so phones must uninstall before installing a newer APK. Never commit the keystore.
- Play Store later: switch the workflow to `bundleRelease` (`.aab`), enrol the keystore in Play App Signing, add a privacy-policy URL on `/install`, and set `targetSdkVersion` to Play's current minimum (Capacitor's `variables.gradle`). Google rejects pure web wrappers only when they add no value; GYMBASE is the owner's own SaaS so it qualifies, but a Trusted Web Activity (Bubblewrap) is the alternative if a review complains.
